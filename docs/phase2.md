# 第二阶段项目文档

## 1. 阶段目标

第二阶段聚焦“实时分析 + 扩展模块对接”，在第一阶段姿态解析基础上完成实时输入、帧级输出统一、进球检测占位可调用、UI 参考姿态与报告生成模块的最小可用版本，并确保可扩展到后续模块。

## 2. 范围与非范围

范围内：

- USB 摄像头实时输入与帧率控制。
- 统一帧级数据结构贯通管线与输出。
- 进球检测模块最小可用实现（事件结构输出）。
- UI 参考姿态模块最小可用实现（模板序列输出）。
- 报告生成模块最小可用实现（文本摘要输出）。
- 接口与配置扩展（枚举、阈值、模板管理）。
- 文档与示例数据完善。

范围外：

- 高精度球轨迹与复杂遮挡处理。
- 训练数据管理与前端实时大屏。
- 账户体系与多用户协作。
- 模型训练与自动标注。

## 3. 交付物

- 进球检测模块：`sport_vision/future/goal_detection.py`。
- UI 参考姿态模块：`sport_vision/future/ui_reference.py`。
- 报告生成模块：`sport_vision/future/reporting.py`。
- 统一接口文档：`docs/phase2_interfaces.md`。
- 第二阶段文档与使用说明：`docs/phase2.md`。

## 4. 统一数据结构

沿用并补充 `docs/phase2_interfaces.md` 中的定义，要求所有新增模块与管线保持一致字段命名和时间戳对齐。

## 5. 验收标准

- 摄像头实时输入可稳定运行，支持手动退出。
- 进球检测、UI 参考姿态、报告模块可被调用并返回结构化结果。
- 输出 JSON 结构符合接口文档定义。
- 关键字段使用枚举或字典配置，避免硬编码。
- Windows + venv 环境可运行。

## 6. 风险与缓解

- 实时性能不足：增加帧率限制与异步处理占位。
- 进球事件误判：先输出低置信度事件，后续再提升算法。
- 模块接口变更：优先保持向后兼容，新增字段不破坏旧结构。

## 7. 任务拆分建议

1. 扩展数据结构与配置：事件类型、模板管理、报告字段。
2. 实时输入优化：帧率限制、异常恢复、稳定退出。
3. 进球检测最小实现：基于占位逻辑输出事件结构。
4. UI 参考姿态最小实现：读取配置或本地模板。
5. 报告生成最小实现：基于结构化输入输出文本摘要。
6. 文档更新与示例补充。
